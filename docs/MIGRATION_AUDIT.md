# 原版功能迁移审计（native-android）

## 迁移原则

- `main` 保留原始 HTML 版本，不在迁移过程中覆盖或删除。
- Android 版本使用 Kotlin 原生界面与原生系统能力，不以 WebView 包装网页。
- 原版四个主页面、视觉语言、动画、交互和播放器操作逐项迁移；没有完成的功能不得伪装成已完成。
- 以原版 `index.html` 为视觉与行为基准。颜色、字体、尺寸、间距、圆角、阴影、图标和动画曲线均应对照原版复核。

## 原版页面与功能清单

### 1. 首页
- 视频总数、已看完数量、本周观看时长统计面板。
- “继续观看”横向卡片列表，显示进度与进度条；可折叠/展开。
- “最近添加”纵向列表；可折叠/展开。
- 点击视频卡片进入播放器。
- 顶部设置入口。

### 2. 片库
- 全部 / 在看 / 已看状态筛选。
- 横向分类筛选：全部分类、我的最爱及用户自建分类。
- 2 列大图与 3 列紧凑网格切换。
- 按添加时间、文件名排序。
- 视频卡片点击播放；长按打开操作菜单。
- 视频操作：立即播放、收藏/取消收藏、移动分类、重命名、自定义封面、移出片库。
- 分类管理：创建分类、删除自建分类。
- 顶部分类、排序、网格模式入口。

### 3. 最近
- 按今天、昨天、更早分组展示视频。
- 卡片显示缩略图、标题、时长/日期信息。
- 单条播放记录清除。
- 清空所有播放进度，但保留视频文件与片库条目。
- 注意：原版此页的部分时间/时长文案目前是静态示例值，迁移时应保留界面意图，并以真实播放记录数据替代静态假数据。

### 4. 记录
- 已看完视频列表。
- 已看完数量、累计时长、已写感想数量统计。
- 每部视频的 0–5 星评分。
- 编辑/保存观影感想。
- 按看完时间、评分排序。
- 搜索入口（原版目前只有搜索输入面板，没有完整搜索结果/筛选逻辑，迁移时需明确补齐实际搜索行为）。

### 5. 全局导航与导入
- 底部胶囊式四栏导航，带滑动指示器动画。
- 主页面之间支持横向滑动切换；横向滚动子区域不应误触发页面切换。
- 右下角悬浮菜单展开/收起动画。
- 快速搜索与导入入口。
- 从相册选择视频、从文件夹导入视频；支持多文件导入。
- 原生实现使用 Android Storage Access Framework / 系统 Photo Picker，并持久化授权 URI。

### 6. 菜单、表单与反馈
- 底部弹出面板、背景遮罩、模糊/淡入/上移动画。
- 搜索输入、导入选项、视频操作、视频排序、记录排序、视图模式。
- 分类管理、重命名、移动分类、评分与感想编辑。
- 单条记录删除、清空播放记录、清空全部数据的二次确认。
- 设置项：允许后台播放、保持屏幕常亮。
- Toast 提示与键盘弹出时的面板适配。

### 7. 全屏播放器
- 视频播放、暂停、播放进度与总时长。
- 点击进度条跳转、拖动进度条预览/定位。
- 速度循环：1.0x、1.25x、1.5x、2.0x、0.75x。
- 长按临时 2.0x，松手恢复当前倍速。
- 双击左/右侧快退/快进 10 秒。
- 左侧上下滑动调节亮度，右侧上下滑动调节音量，中间横向滑动调节进度。
- 播放控制 UI 自动隐藏；锁屏防误触与解锁提示。
- 横屏/竖屏切换。
- 播放完成后标记已看完、进度 100%，并更新记录页。
- 根据保存的进度续播。
- 设置开启时保持屏幕常亮。
- 设置允许后台播放；原生版本需使用 MediaSession 与前台播放服务实现真正的后台播放。

## 数据模型迁移

原版视频条目字段：
- `id`、`name`、`size`、`date`
- `progress`、`status`（all / playing / watched）
- `isFav`、`category`、`bgIndex`
- `review`、`rating`、`hasThumb`

原版分类默认值：`全部分类`、`我的最爱`；用户可创建和删除其他分类。

原版设置：`bgPlay`、`wakeLock`。

原生版本持久化方案：
- Room 保存视频元数据、分类、播放进度、收藏、评分、感想和设置。
- 视频使用 SAF 返回的 content URI，并持久化 URI 读取授权；不把视频二进制复制进数据库。
- 缩略图与自定义封面保存到应用私有持久化存储，数据库只保存文件标识/路径。
- 删除视频条目、清空播放记录、清空全部数据分别实现，不能混淆数据保留范围。
- 兼容旧版 localStorage 数据不是自动可行的：旧版视频 URI/文件引用从未保存，故只能迁移可读取的元数据；视频文件需要用户重新授权导入。

## 原版已发现的限制与迁移修复项

1. `fileCache` 和 `thumbCache` 仅存在 JavaScript 内存中。应用重启/页面刷新后，视频文件引用与缩略图会丢失。
2. localStorage 只保存视频元数据、分类与设置，不保存可恢复播放的视频 URI。
3. 最近页部分时长/时间显示为写死的演示值，不是可靠的播放历史数据。
4. 记录页搜索入口尚未实现完整搜索结果与筛选逻辑。
5. 播放进度保存使用随机概率触发，不能保证稳定保存；原生版本应在合理时间间隔及生命周期节点可靠写入。
6. 原版的播放后台设置只保存了开关状态；原生版本必须落实为 MediaSession/前台服务能力，而不是只显示开关。
7. 原版清空全部数据只清空 JS 数据和缓存；原生版本还需正确清理数据库关联的封面缩略图文件与持久授权。

## 原生技术路线

- Kotlin + Jetpack Compose：页面布局、状态、动画、弹出面板与手势。
- Room：本地结构化数据。
- Android Photo Picker / ACTION_OPEN_DOCUMENT：视频选择与持久 URI 权限。
- AndroidX Media3 ExoPlayer：播放引擎、倍速、进度控制、音量与媒体会话。
- MediaSessionService：后台播放与系统媒体控制。
- Window brightness / Window flags：亮度与保持屏幕常亮。
- Android 原生构建：Gradle Wrapper、固定插件/依赖版本、GitHub Actions。

## 分阶段交付与验收

1. **原版审计与工程基座**：完成这份功能清单；建立独立分支；建立可构建的 Kotlin Android 工程。
2. **原生 UI**：四个主页面、底部导航、卡片/网格、分类栏、底部面板、悬浮菜单，按原版尺寸与样式实现。
3. **数据与导入**：Room、视频 URI 授权、缩略图/封面持久化、分类/收藏/排序/重命名/删除/记录。
4. **播放器**：Media3、续播、进度持久化、倍速、手势、锁屏、横屏、常亮、后台播放。
5. **逐项回归**：按本清单核对页面、交互、数据保留规则和播放器操作。
6. **自动构建与交付**：GitHub Actions 构建 APK；确认构建成功后提供安装包。

## 验收规则

- 原版功能清单中的每一项都必须有对应实现或明确标记为未完成。
- 不以空页面、静态截图或 WebView 作为原生功能的替代。
- 不修改 `main` 的原版文件；迁移只在 `native-android` 分支进行。
- 每次提交说明本次实现范围与尚未完成的内容。
